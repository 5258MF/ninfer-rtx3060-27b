最新窗口分配（Swift 0.1.2／Bonsai 0.1.3）
===========================================
总驻留容量由启动时的空闲显存确定；系统、developer 指令和工具说明按实际 token 数完整保留。
256K 总上下文：检索目标 32K–36K，优先 36K；128K：16K–18K，优先 18K。检索不包含固定开头。
剩余容量留给本轮思考和正文，至少预留 8K，没有固定 16K/32K 上限。不足时先缩检索；开头和 8K 输出放不下会明确拒绝。
OUT/ANSWER、SYS/SINK、WINDOW 的旧手动值会迁移为自动分配。启动前生成接入信息，Harness 可先配置 contextWindow/maxTokens；引擎收到请求后自动降低本轮输出预算。
低显存下能运行不代表能可靠召回全部超长历史。看图时仍有临时上传和计算缓冲，视觉权重放内存不表示所有显存峰值消失。
下面的旧档位、输出限制或固定开头数字属于历史说明，以本段和当前启动器显示为准。

ninfer Swift 1.5 懒人包 使用说明
================================

一、这是什么
  在 12 GB 显存的 NVIDIA 显卡上本地跑 Swift-1.5 Qwen3.8-27B（UkisAI 的 Swift 1.5 微调，IQ2_S 量化）。
  和 12G 懒人包（Swift-Bonsai-2）比：模型质量更好（同一测试集 PPL 低约 18%），上下文更长（最多 256K），
  用的是另一套新引擎（Ryan-gsq 的 ninfer 分支 + KVMem 移植 + 3060 优化）。
  RTX 3060 12G 实测：生成约 43 token/秒（MTP 输出头选"精简"约 47），日常用将近 50 token/秒。

二、电脑要求
  - 显卡：NVIDIA，12 GB 以上显存，RTX 30 系（算力 8.6）。RTX 40 系（算力 8.9）也能跑，但没实测过。
    显卡的 SM 数由引擎启动时自动识别，3060 / 3080 / 4070 等不用改任何东西。
    8 GB 卡请用 8G 懒人包；RTX 50 系、20 系用不了这个包。
  - 显卡驱动：要支持 CUDA 13，建议 580 以上版本
  - 内存：建议 32 GB（KVMem 把完整对话记录放内存，200K 约 8 GB，256K 约 10 GB；引擎本身还要约 14 GB）
  - 系统：Windows 10 / 11，64 位
  - 硬盘：最后约 11.2 GB（程序 1.7 GB + 模型 9.5 GiB）；第一次准备模型时临时要约 21 GB
  - 网络：第一次用要下载模型（约 9.55 GiB，魔搭社区，国内直连）

  不用另外配环境：只要装好 NVIDIA 显卡驱动（580 以上）就行。
  不用装 CUDA、Python、VC++ 运行库——引擎要的文件都在 engine 文件夹里。
  （查驱动版本：在 cmd 里输入 nvidia-smi，右上角 Driver Version）

三、怎么用
  1. 解压到一个路径简单的地方（例如 D:\ninfer-swift15），双击「启动.bat」，会先显示当前配置：
       回车 = 用这套配置启动
       C    = 一步步重新选（下面第五节）
       R    = 重新读空闲显存（关掉别的程序以后按一下，窗口会变大）
       Q    = 退出
     第一次用直接回车就行（默认 rk4v4 + 完整头，总上下文 200K，输出自动）。没有倒计时，不按键就一直等。
     第一次启动会先下载模型、再用补丁转换一下（见第八节），以后就不用了。
  2. 窗口里出现 "listening" 就能用了（第一次大约 1 分钟）。
  3. 双击「测试.bat」可以检查是否正常，会显示一句回答和速度。
  4. 用完直接关掉启动窗口就行。
  注意：同一时间只能开一个引擎。已经有 ninfer-serve 在跑时，启动器会问你要不要关掉它（K）。

四、KVMem 是什么、窗口怎么分
  完整的对话记录放在内存里，显存里只放一个"窗口"。每一轮从内存里挑和问题相关的内容放进窗口，
  所以总上下文可以远大于显存（rk4v4 最多 256K）。窗口 = 单次输出 + 开头（系统提示，固定保留）+ 检索和最近内容。
  - 窗口大小按启动时的空闲显存自动算（整卡留约 150–200 MiB），放不下会自动缩小重试。
  - 单次输出选"自动"时：
      rk4v4 + 完整头：检索窗口（含开头）优先留 36K，剩下给输出，输出最多 32K、最少 8K。3060 上约 26–28K。
      其他组合（rk8v4 或精简头）：窗口小，开头之外输出和检索各一半，总上下文最多 128K。
  - 单次输出（含思考）整段留在显存里不会被挤掉；超过上限会被截断，写很长的东西请分几步。
  - 历史超出窗口以后，每一轮只把新内容重新算一遍。

  四种组合（RTX 3060 12G 上的数，空闲显存约 11.2 GB 时）：
    组合               总上下文            窗口      自动输出   检索窗口   速度
    rk4v4 + 完整头     推荐 200K，最多 256K  约 63K     约 27K     36K        约 43 token/秒（推荐，默认）
    rk4v4 + 精简头     最多 128K           约 44K     约 18K     约 26K     约 47 token/秒
    rk8v4 + 完整头     最多 128K           约 43K     约 17K     约 26K     慢 14–22%
    rk8v4 + 精简头     最多 128K           约 31K     约 11K     约 19K
  显存更大的卡窗口会自动变大（有上限），16 GB 以上的卡多出来的显存暂时用不上。

五、改参数
  方法 1（最省事）：双击「启动.bat」，按 C，一步步选：
    第 1 步  KV 量化：rk4v4（推荐）/ rk8v4
    第 2 步  MTP 输出头：完整（推荐，窗口大）/ 精简（快约 10%，窗口小）
    第 3 步  看图 开 / 关（视觉权重放内存，开着不多占显存）
    第 4 步  总上下文
    第 5 步  单次输出上限（推荐"自动"）
    第 6 步  开头固定保留（推荐 8K，dsh 的系统提示约 8K）
    第 7 步  思考长度上限（推荐不限）
    每一步都标了推荐值和上限，直接回车 = 保持现在的值；也可以直接输入数字（例如 150k）。
    选完回到配置总览，回车启动；选好的值会自动存进「设置.ini」，下次回车直接用。
  方法 2：用记事本打开「设置.ini」修改，保存后重新运行「启动.bat」。每一项都有说明。
    端口、监听地址（局域网共享）、API_KEY、模型名只能在这里改。
    还可以在 设置.ini 里调整 v3 引擎新增的推理控制开关：
      - POST_THINKING=1（默认开启）：思考结束（</think>）后自动把采样温度降到 0.2（可通过 POST_THINKING_TEMP / POST_THINKING_TOP_P / POST_THINKING_TOP_K / POST_THINKING_SAMPLER 自定义），兼顾思考阶段的发散性与正文/代码输出的稳定性。
      - ADAPTIVE_MTP=0/1：是否开启自适应投机解码草稿宽度（--adaptive-mtp）。
      - RECOVER_INVARIANT=1（默认开启）：遇到内部状态异常时自动恢复当前请求（--recover-invariant-failures），避免整个服务进程退出。
  其他：
    启动.bat last      直接用上次的配置启动，不显示菜单
    启动.bat dryrun    只显示最后会用的引擎参数，不启动、不下载（检查设置用）

六、客户端（harness）怎么接
  最省事：启动以后，打开这个文件夹里自动生成的「接入信息.txt」，照着填。
  里面是当前配置的全部数值，还有一份 DeepSeek Harness（dsh）可以直接用的配置。
  启动窗口里也会显示一份简要的。

  通用填法（Cherry Studio、Chatbox、Open WebUI、Cline、Continue 等，选“OpenAI 兼容 / 自定义”）：
    接口地址（Base URL）：http://127.0.0.1:8084/v1
    模型名：qwen3.8-27b
    API Key：设置.ini 里没设就随便填（例如 none），但很多客户端不许空着
    上下文窗口：和「总上下文」一样（默认 204800）
    最大输出：以「接入信息.txt」为准（"自动"时每次启动按显存算，3060 上约 26624–27648）
    图片输入：支持（关了看图就不支持）
    工具调用：支持

  为什么这两个数要填对：
    - 上下文窗口填大了，客户端会塞进超过引擎能接收的内容，请求会报错；填小了，客户端会过早压缩/丢弃历史。
    - 最大输出填得比实际大，引擎会在上限处截断（finish_reason = length）。

  dsh 用户注意：改完 cordis.patch.yml 要完全退出 dsh（包括右下角托盘图标）再打开。
  dsh 开着的时候它会把自己内存里的旧值写回这个文件，新改的模型名、输出上限就丢了。

  其他：
    - 也支持 Anthropic Messages（/v1/messages）和 OpenAI Responses（/v1/responses）格式。
    - 思考内容在 reasoning_content 字段（DeepSeek 格式）。请求里加 "enable_thinking": false 可以关思考。
    - 思考档位（reasoning_effort）只有 low / medium / xhigh，加上关思考，一共四档。
    - 一次只处理一个请求，多个对话同时发会排队。
    - 想让局域网里其他电脑用：设置.ini 里 HOST=0.0.0.0，并设置 API_KEY；接入信息.txt 里会列出本机的局域网地址。

七、常见问题
  - 提示“已经有一个模型在运行”：按 K 关掉旧的再启动，或者按 Q 继续用旧的。
  - 提示“端口被占用”：改 设置.ini 里的 PORT。
  - 启动报显存不足（out of memory）：启动器会自动缩小窗口重试；还不行就关掉占显存的程序
    （游戏、浏览器硬件加速、其他 AI 程序等），或按 C 把单次输出调小。
  - 生成突然变得很慢：多半是显存不够、被系统挪了一部分到内存。关掉占显存的程序后重新启动。
  - 报 cudaMallocHost / bad allocation：内存不够。按 C 把总上下文调小（内存预留跟着变小）。
  - 显卡不是算力 8.6 / 8.9：这个包是给 RTX 30 / 40 系编译的，其他显卡用不了。
  - 窗口一闪就没了：在文件夹地址栏输入 cmd 回车，再输入 启动.bat，就能看到错误信息。
  - 模型下载慢或断了：直接关掉窗口，重新运行 启动.bat，会接着下（不会从头来）。
  - 提示"文件校验不对"：把 model 文件夹里的 .bad 文件删掉，重新运行 启动.bat 下载。
  - 提示"补丁文件缺失"：patch 文件夹不全，请重新解压懒人包。
  - 引擎日志在 logs 文件夹（只留最近 10 个），出问题时可以把最新的发给作者。

八、模型下载和转换
  包里不带模型。第一次启动时，选好配置按回车后，会显示要下载的模型、大小和保存位置，再按一次回车开始下载。
    来源：https://www.modelscope.cn/models/fyb423/Swift-1.5-Qwen3.8-27B-GSQ-RCO-NInfer
    文件：swift15_iq2s_mtp.ninfer（10,257,632,000 字节，约 9.55 GiB；说明页上写的是旧名 swift15_iq2_s.ninfer，是同一个文件）
  - 用的是 Windows 自带的 curl 下载，窗口里会显示进度和速度；中途关掉窗口，下次启动会接着下。
  - 下载时先存成 xxx.ninfer.part，下完自动校验 SHA256，对了才改成正式文件名。
  - 下完以后自动用 patch 文件夹里的补丁生成 swift15_iq2_s_mtpq4.ninfer（10,155,600,640 字节）：
    只把 MTP 草稿头（投机解码用的小头，一次先猜 3 个字）转成 Q4，其余部分原样复制。
    省约 95 MiB 显存给窗口，实测速度、猜中率不变；回答内容不受影响（每个字都由主模型核对）。
    转完再校验一次 SHA256，然后删掉原始文件。
  - 也可以自己用浏览器或下载工具从上面的网页（文件和版本）下载 swift15_iq2s_mtp.ninfer，放进 model 文件夹（文件名不要改），
    启动时会直接转换，不再下载。
  - 下载前会先检查显卡和硬盘空间，不合适的电脑不会白下 10 GB。

九、文件夹里有什么
  启动.bat / 测试.bat     双击用
  设置.ini                参数
  launcher\               启动器脚本
  engine\                 引擎 ninfer-serve.exe 和全部 DLL
  patch\                  把原版模型转成 MTP Q4 版的补丁（约 195 MB）
  model\                  模型（包里是空的，第一次启动自动下载、转换到这里）
  logs\                   引擎日志（自动生成）
  接入信息.txt            客户端怎么填（每次启动自动生成）
  SHA256SUMS.txt          包内核心文件 SHA256 清单
  verify-kit-manifest.ps1 解压完整性与中文文件名乱码自检脚本
  verify-arch-engine.ps1  引擎实机全链路验收脚本（含正负对照与中段大海捞针测试）

版本更新（2026-10-03，首次显卡校准修复）
  - 包含此前的 KV 容量曲线修复，以及首次显卡自动校准的修复：
    精简版只测试已编译的 int8 / rk8v4 / rk4v4 内核，跳过未编译的 E8 内核。
    使用默认 rk4v4 的用户无需修改 KV 格式或关闭 SM 自动识别。
  - 首次遇到未校准显卡时，需要先测量路线，会比之后的启动慢；等到 listening 再使用。
  - engine 内已包含 msvcp140.dll、vcruntime140.dll、vcruntime140_1.dll。
    请完整解压，保持这些文件和 ninfer-serve.exe 在同一目录，不要只复制 EXE。
    如 Windows 提示这些 DLL 找不到或入口点不存在，可参考微软官方 VC 运行库下载说明：
    https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist
    DLL 加载错误与引擎输出的 small_t_i8 / NINFER_SLIM_3060 校准错误需要分别处理。
  - 旧模型无需重新下载或转换；升级后正常运行 启动.bat 即可。

2026-10-04：启动与验收共性修复
  - 使用 listening 日志判断引擎已开始服务，不再按运行不足 120 秒猜测启动失败。
    启动期的容量错误才触发缩窗；运行中退出使用有上限的重启。
  - 缩窗后同步本次实际输出上限到客户端接入信息（文字及 YAML）；
    本机启动器在允许同步时也更新 dsh。保存的个人配置不写入临时缩窗结果。
    输出预算减少时，思考预算一并限制到有效输出范围。
  - 启动失败返回非零状态。
  - 引擎验收返回码：0 为本次检查通过，1 为失败，2 为无法确认。
    FAIL 和 INCONCLUSIVE 不再被当作成功；负对照必须回答 NONE。
  - 验收新增缩短历史、实际输出封顶、真实工具结果回传、Messages / Responses 和看图。
    默认使用小窗口与 512 token 输出上限，不代表已经测满 256K 或生成满 32K。
    多工具 required/any 按 Auto 处理，不保证调用；strict 不提供严格 Schema 约束。
  - 如模型不在默认 model 目录，验收时传 -ModelPath 指定已转换文件：
      powershell -NoProfile -ExecutionPolicy Bypass -File verify-kit-manifest.ps1
      powershell -NoProfile -ExecutionPolicy Bypass -File verify-arch-engine.ps1 -ModelPath <模型文件>
    默认请求等待为 1800 秒；客户端仍需自行设置足够的等待时间。
  - 此轮修改启动与验收脚本，不改变模型量化、引擎二进制或容量配比。
