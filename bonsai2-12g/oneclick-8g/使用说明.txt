最新窗口分配（Swift 0.1.2／Bonsai 0.1.3）
===========================================
总驻留容量由启动时的空闲显存确定；系统、developer 指令和工具说明按实际 token 数完整保留。
256K 总上下文：检索目标 32K–36K，优先 36K；128K：16K–18K，优先 18K。检索不包含固定开头。
剩余容量留给本轮思考和正文，至少预留 8K，没有固定 16K/32K 上限。不足时先缩检索；开头和 8K 输出放不下会明确拒绝。
OUT/ANSWER、SYS/SINK、WINDOW 的旧手动值会迁移为自动分配。启动前生成接入信息，Harness 可先配置 contextWindow/maxTokens；引擎收到请求后自动降低本轮输出预算。
低显存下能运行不代表能可靠召回全部超长历史。看图时仍有临时上传和计算缓冲，视觉权重放内存不表示所有显存峰值消失。
下面的旧档位、输出限制或固定开头数字属于历史说明，以本段和当前启动器显示为准。

Bonsai2 0.1.2（2026-10-04）
KVMem 默认采用 CPU 检索索引，256K 时约省 400 MiB 显存。
窗口按当前空闲显存计算；自动回答优先留 36K 历史，达到输出上限后所有余量给历史。
8G rk8v4 自动输出 8K–16K；其他模式 8K–32K。手动回答保持原值。
WINDOW=0 自动使用剩余历史空间；正数是手动历史上限。8G 方案仍需真实 8GB 卡验收。
云盘旧链接不会自动更新；本机新 ZIP 与旧包不同。

ninfer 3060 8GB 一键包 使用说明
==============================

一、电脑要求
  - 显卡：NVIDIA RTX 3060 8GB（其他 8 GB 的 RTX 30 系应该也能跑，没测过；12 GB 的卡请用 12G 版一键包，更快、上下文更大）
  - 显卡驱动：要支持 CUDA 13，建议 580 以上版本
  - 内存：16 GB 能用普通模式；KVMem 模式建议 32 GB
  - 系统：Windows 10 / 11，64 位
  - 硬盘：最后约 7.5 GB（程序约 1 GB + 模型 6.4 GiB）；第一次准备模型时临时要约 14 GB
  - 网络：第一次用要下载模型（约 6.6 GiB，魔搭社区，国内直连）

  不用另外配环境：只要装好 NVIDIA 显卡驱动（580 以上）就行。
  不用装 CUDA、Python、VC++ 运行库——引擎要的文件都在 engine 文件夹里。
  （查驱动版本：在 cmd 里输入 nvidia-smi，右上角 Driver Version；太旧就到 NVIDIA 官网下载 Game Ready 或 Studio 驱动更新）

  8G 版和 12G 版的区别：
    - 模型用 Swift-Bonsai-2 的 ptq1 版（比 12G 版用的 pq2 小 1.2 GB），MTP 部分再转成 Q4（省约 225 MB 显存）
    - 词嵌入和视觉权重放内存，KV 默认用 rk8v4，默认档以引擎约 7.5 GiB 的历史预算配比为目标；这不是硬性限额，48K 可选档会超过它
    - 生成速度比 12G 卡慢约 30%（显存带宽小）

二、怎么用
  1. 双击「启动.bat」，会先显示当前配置：
       回车   = 用这套配置启动
       C      = 一步步重新选（下面第五节）
       N/K/R/V = 直接换成 普通 / KVMem / 普通 rk4v4 / KVMem+rk4v4 模式
       Q      = 退出
     第一次用直接回车就行（默认 KVMem 模式）。没有倒计时，不按键就一直等。
     第一次启动会先下载模型、再转换成 8G 用的版本（见下面第八节），以后就不用了。
  2. 窗口里出现 "listening" 就能用了（第一次大约 30～60 秒）。
  3. 双击「测试.bat」可以检查是否正常，会显示一句回答和速度。
  4. 用完直接关掉启动窗口就行。
  注意：同一时间只能开一个引擎。

三、四种模式怎么选
  模式              上下文     单次回答上限   说明
  普通 N            56K        32K            全部在显存，最快。推荐
  KVMem K           256K       16K            推荐（默认）。长对话时历史放内存，按问题挑相关部分放回显存
  普通 rk4v4 R      84K        32K            不推荐：KV 压得更狠，能多放，但慢 10–15%、质量差约 0.3%
  KVMem+rk4v4 V     256K       32K            不推荐：同上；显存里放得更多（64K），所以一次回答能到 32K
  KVMem 模式显存里放 44K（检索窗口 28K + 回答 16K）。显示器接在核显上（这张卡只跑模型）时，
  向导里"显存档"可以选 48K（窗口 32K + 回答 16K），旧引擎约用 7760 MiB；新版短请求采样增量为 7823 MiB。实际还要给系统留显存，不能保证 8GB 卡可用。
  KVMem+rk4v4 模式显存里放 64K（检索窗口 32K + 回答 32K）。
  KVMem 模式下一次回答（含思考）超过上限会被截断，写很长的东西请分几步。
  历史被挤出显存后，会把这一轮的新输入按新挑的内容重新算一遍（最多 6144 token），
  上限可在 设置.ini 的 KVMEM_REPLAY_MAX 里改。

  历史实测（旧引擎，在 12GB 卡上测量引擎占用，不是真实 8GB 硬件验收）：
    普通 56K 7628 MiB、KVMem 7659 MiB（48K 档 7760）、普通 rk4v4 84K 7627 MiB、KVMem+rk4v4 7617 MiB（一次写满 32K 回答后也是 7617）；
    四种都通过了工具调用、看图、思考、长文测试；两个 KVMem 模式在 26 万 token 里藏一句话都能找到。

四、客户端（harness）怎么接
  最省事：启动以后，打开这个文件夹里自动生成的「接入信息.txt」，照着填。
  里面是当前模式的全部数值，还有一份 DeepSeek Harness（dsh）可以直接用的配置。
  启动窗口里也会显示一份简要的。

  通用填法（Cherry Studio、Chatbox、Open WebUI、Cline、Continue 等，选“OpenAI 兼容 / 自定义”）：
    接口地址（Base URL）：http://127.0.0.1:8084/v1
    模型名：qwen3.8-27b
    API Key：设置.ini 里没设就随便填（例如 none），但很多客户端不许空着
    上下文窗口、最大输出：按下表，和你启动的模式一致
    图片输入：支持（设置.ini 里 VISION=0 时不支持）
    工具调用：支持

    模式              上下文窗口   最大输出（含思考）
    普通 N            57344        32768
    KVMem K           262144       16384
    普通 rk4v4 R      86016        32768
    KVMem+rk4v4 V     262144       32768
    （改过 设置.ini 的话以「接入信息.txt」为准）

  为什么这两个数要填对：
    - 上下文窗口填大了，客户端会塞进超过引擎能接收的内容，请求会报错；填小了，客户端会过早压缩/丢弃历史。
    - 最大输出填得比上表大，引擎会在上限处截断（finish_reason = length）。

  其他：
    - 也支持 Anthropic Messages（/v1/messages）和 OpenAI Responses（/v1/responses）格式。
    - 思考内容在 reasoning_content 字段（DeepSeek 格式）。请求里加 "enable_thinking": false 可以关思考。
    - 思考档位（reasoning_effort）只有 low / medium / xhigh，加上关思考，一共四档。
    - 一次只处理一个请求，多个对话同时发会排队。
    - 想让局域网里其他电脑用：设置.ini 里 HOST=0.0.0.0，并设置 API_KEY；接入信息.txt 里会列出本机的局域网地址。

五、改参数
  方法 1（最省事）：双击「启动.bat」，按 C，一步步选：
    第 1 步  KVMem 开 / 关
    第 2 步  KV 量化：rk8v4（推荐）/ rk4v4（不推荐）
    （KVMem + rk8v4 时多一步：显存档 默认 / 48K）
    然后     看图 开 / 关
    然后     总上下文
    然后     单次回答上限（KVMem 模式下还有一步：检索窗口）
    最后     思考长度上限
    每一步都标了推荐值和上限，直接回车 = 保持现在的值；也可以直接输入数字（例如 48k），超过上限会让你重输。
    选完回到配置总览，回车启动；选好的值会自动存进「设置.ini」，下次回车直接用。
  方法 2：用记事本打开「设置.ini」修改，保存后重新运行「启动.bat」。每一项都有说明。
  方法 2：用记事本打开「设置.ini」修改，保存后重新运行「启动.bat」。每一项都有说明。
          常改的两项：POST_THINK_TEMP（思考写完后自动降温，默认 0.2，填 0 关掉）、RETRY（引擎意外退出自动重启次数）。
  方法 3：命令行临时改（不改设置文件）。在这个文件夹的地址栏输入 cmd 回车，然后：
    启动.bat kvmem                      直接用 KVMem 模式，不显示菜单
    启动.bat normal PORT=8085           普通模式，换个端口
    启动.bat kvmem KVMEM_ANSWER=8192    回答上限改成 8K（窗口可以相应加大）
    启动.bat normal --greedy            在最后追加引擎参数
    启动.bat kvmem DRYRUN=1             只显示最后会用的参数，不启动（检查设置用）
  「设置.ini」里的任何一项都能写成 名字=值 放在命令行里。
  测试别的端口：测试.bat PORT=8085

六、常见问题
  - 提示“已经有一个 ninfer-serve 引擎在运行”：先关掉旧的引擎窗口；找不到窗口就在任务管理器里结束 ninfer-serve.exe（或 ninfer-serve-rk4.exe）。
  - 提示“端口已被占用”：改 设置.ini 里的 PORT。
  - 启动报显存不足（out of memory）：关掉占显存的程序（游戏、浏览器硬件加速、其他 AI 程序等），或者把上下文调小。
    8 GB 卡上模型自己就用到 7.5 GB，桌面和其他程序一共只有约 0.5 GB 可用。
  - 启动报显存不足（out of memory）：关掉占显存的程序（游戏、浏览器硬件加速、其他 AI 程序等），或者把上下文调小。
    8 GB 卡上模型自己就用到 7.5 GB，桌面和其他程序一共只有约 0.5 GB 可用。
  - 只是轻微不够时，启动器会自己处理：引擎报“显存不够”，它就把显存里的部分（检索窗口）缩小一点再启动，最多试 3 次，
    缩完会打印这次实际用的数值（回答长度不变，只缩历史窗口）。下次关掉占显存的程序再启动就恢复原样。
  - 想看完整报错：打开 logs 文件夹，最新那个 engine-*.log 就是这次运行的完整日志（只保留最近 10 个）。
  - 生成突然变得很慢：多半是显存不够、被系统挪了一部分到内存。关掉占显存的程序，或者把上下文调小一档。
  - 报 cudaMallocHost / bad allocation：内存不够。KVMem 模式要多用约 10 GB 内存。
  - 显卡不是算力 8.6：这个包是给 RTX 30 系编译的，其他显卡用不了。
  - 窗口一闪就没了：在文件夹地址栏输入 cmd 回车，再输入 启动.bat，就能看到错误信息。
  - 模型下载慢或断了：直接关掉窗口，重新运行 启动.bat，会接着下（不会从头来）。
  - 提示"文件校验不对"：把 model 文件夹里的 .bad 文件删掉，重新运行 启动.bat 下载。
  - 提示"补丁文件缺失"：patch 文件夹不全，请重新解压一键包。

八、模型下载和转换
  包里不带模型。第一次启动时，选好配置按回车后，会显示要下载的模型、大小和保存位置，再按一次回车开始下载。
    来源：https://www.modelscope.cn/models/fyb423/Swift-Bonsai-2-27B-NInfer
    文件：bonsai2_27b_swift_ptq1.ninfer（7,047,407,628 字节，约 6.6 GiB）
  - 用的是 Windows 自带的 curl 下载，窗口里会显示进度和速度；中途关掉窗口，下次启动会接着下。
  - 下载时先存成 xxx.ninfer.part，下完自动校验 SHA256，对了才改成正式文件名。
  - 下完以后自动用 patch 文件夹里的补丁转换成 Swift-Bonsai-2-ptq1-mtpq4.ninfer（6,821,799,948 字节），
    只把 MTP（投机解码用的小头）转成 Q4，其余部分原样复制。约 1–2 分钟，转完再校验一次 SHA256，
    然后删掉原始文件。
  - 也可以自己用浏览器或下载工具从上面的网页下载 bonsai2_27b_swift_ptq1.ninfer，放进 model 文件夹（文件名不要改），
    启动时会直接转换，不再下载。
  - 下载前会先检查显卡和硬盘空间，不合适的电脑不会白下 7 GB。

九、自检和实机验收（可选）
  在包目录打开 CMD 后运行：
    powershell -NoProfile -ExecutionPolicy Bypass -File verify-kit-manifest.ps1
    powershell -NoProfile -ExecutionPolicy Bypass -File verify-arch-engine.ps1 -Mode kvmem
    powershell -NoProfile -ExecutionPolicy Bypass -File verify-arch-engine.ps1 -Mode kvrk4

  包自检核对两个引擎、DLL、补丁、启动器和中文入口文件。
  引擎验收只支持两个 KVMem 模式，默认用较小窗口和 512 token 输出上限，
  会占用显存；开始前关闭其他模型。可以用 -ModelPath 指定已转换模型。

  验收包括：未显式设置 NO_REBAKE 的启动、NVML 预算、短问答、超窗正负对照、
  多轮追问、中途截断历史、实际输出封顶、工具参数接收、工具结果回传及最终回答、
  Anthropic Messages / OpenAI Responses 基本请求、图片左右颜色识别。
  返回码 0 表示本次执行的检查通过，1 表示失败，2 表示无法确定。
  生成提前停止或正向藏针被截断时不会再算作全绿。

  这是回归测试，不代表真实 8GB 显卡、所有窗口、256K 长文和 32K 长输出都已验证。
  多工具 required/any 当前按 Auto 处理，不保证必定调用工具；
  strict 声明不提供严格 JSON Schema 约束；思考预算仍有原始请求校验。

十、启动与日志修复（2026-10-04）
  - 自动缩窗只使用当前这一次启动报告的容量差额，其他报错不会误读旧日志。
  - KVMem 保留当前输出预算，检索窗口至少 16K；普通模式必要时降低输出。
  - 是否已出现 listening 用于区分启动失败和运行中退出，不按运行秒数猜测。
  - 本次实际上下文和输出会同步到接入信息中的文字及 YAML 示例，保存的设置不改。
  - API Key 在命令显示与引擎日志中脱敏；失败退出会返回非零状态。
  - HTTP 空闲连接保活为 120 秒，读/写超时各 300 秒，不是推理的总时限。
    客户端仍可能自行超时；首次输入 256K 时，请给客户端预留至少 20 分钟等待。
  - recover-invariant-failures 只尝试恢复支持的部分内部状态错误，并有重试上限。
  - 本次修复没有增加模式容量，也没有建立新的速度或回答质量提升结论。
