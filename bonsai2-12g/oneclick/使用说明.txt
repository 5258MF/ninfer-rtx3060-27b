ninfer 3060 一键包 使用说明
==========================

一、电脑要求
  - 显卡：NVIDIA RTX 3060 12GB（其他 RTX 30 系也能跑，但参数是按 3060 12G 调的）
  - 显卡驱动：要支持 CUDA 13，建议 580 以上版本
  - 内存：16 GB 能用普通模式；KVMem 模式建议 32 GB
  - 系统：Windows 10 / 11，64 位
  - 硬盘：约 10 GB（程序约 0.5 GB + 模型 7.7 GiB）
  - 网络：第一次用要下载模型（约 7.7 GiB，魔搭社区，国内直连）

  不用另外配环境：只要装好 NVIDIA 显卡驱动（580 以上）就行。
  不用装 CUDA、Python、VC++ 运行库——引擎要的文件都在 engine 文件夹里。
  （查驱动版本：在 cmd 里输入 nvidia-smi，右上角 Driver Version；太旧就到 NVIDIA 官网下载 Game Ready 或 Studio 驱动更新）

二、怎么用
  1. 双击「启动.bat」，会先显示当前配置：
       回车   = 用这套配置启动
       C      = 一步步重新选（下面第五节）
       P      = 设置显卡功耗上限（默认可设 135W 降温防撞温度墙，开机自动生效）
       N/K/R/V = 直接换成 普通 / KVMem / rk8v4 / KVMem+rk8v4 模式
       Q      = 退出
     第一次用直接回车就行（默认 Swift 模型 + KVMem 模式）。没有倒计时，不按键就一直等。
     第一次启动会先下载模型（见下面第八节），下完以后就不用再下了。
  2. 窗口里出现 "listening" 就能用了（第一次大约 30～60 秒）。
  3. 双击「测试.bat」可以检查是否正常，会显示一句回答和速度。
  4. 用完直接关掉启动窗口就行。
  注意：同一时间只能开一个引擎。

三、四种模式怎么选
  模式          上下文     单次回答上限   说明
  普通 N        88K        32K            全部在显存，最稳
  KVMem K       256K       自动 8K–40K    推荐。检索上限 36K，显存余量全给回答（保底 8K）
  rk8v4 R       112K       32K            全部在显存，KV 用更省的格式，质量损失约 0.1%
  KVMem+rk8v4 V 256K       自动 8K–64K    显存更省；检索上限 36K，显存余量全给回答（保底 8K）
  （普通、rk8v4 的上下文已经是上限。KVMem 的"检索窗口 + 单次回答"合计最多 76K，KVMem+rk8v4 最多 100K，
    也可在向导第 6 步手动调整输出窗口（8K–52K/76K）和检索窗口（16K–36K））
  KVMem 模式下一次回答（含思考）超过上限会被截断，写很长的东西请分几步。
  KVMem 两种模式用的是第十轮引擎（2026-10-03）：工具循环里也按用户问题挑历史；
  历史被挤出显存后，会把这一轮的新输入按新挑的内容重新算一遍（最多 6144 token，约多 12 秒），
  上限可在 设置.ini 的 KVMEM_REPLAY_MAX 里改。

四、客户端（harness）怎么接
  最省事：启动以后，打开这个文件夹里自动生成的「接入信息.txt」，照着填。
  里面是当前模式的全部数值，还有一份 DeepSeek Harness（dsh）可以直接用的配置。
  启动窗口里也会显示一份简要的。

  通用填法（Cherry Studio、Chatbox、Open WebUI、Cline、Continue 等，选“OpenAI 兼容 / 自定义”）：
    接口地址（Base URL）：http://127.0.0.1:8084/v1
    模型名：qwen3.8-27b
    API Key：设置.ini 里没设就随便填（例如 none），但很多客户端不许空着
    上下文窗口、最大输出：按下表，和你启动的模式一致
    图片输入：支持（设置.ini 里 VISION=0 时不支持）
    工具调用：支持

    模式          上下文窗口   最大输出（含思考）
    普通 N        90112        32768
    KVMem K       262144       自动，按接入信息.txt
    rk8v4 R       114688       32768
    KVMem+rk8v4 V 262144       自动，按接入信息.txt
    （改过 设置.ini 的话以「接入信息.txt」为准）

  为什么这两个数要填对：
    - 上下文窗口填大了，客户端会塞进超过引擎能接收的内容，请求会报错；填小了，客户端会过早压缩/丢弃历史。
    - 最大输出填得比上表大，引擎会在上限处截断（finish_reason = length）。

  其他：
    - 也支持 Anthropic Messages（/v1/messages）和 OpenAI Responses（/v1/responses）格式。
    - 思考内容在 reasoning_content 字段（DeepSeek 格式）。请求里加 "enable_thinking": false 可以关思考。
    - 思考档位（reasoning_effort）只有 low / medium / xhigh，加上关思考，一共四档。
    - 一次只处理一个请求，多个对话同时发会排队。
    - 想让局域网里其他电脑用：设置.ini 里 HOST=0.0.0.0，并设置 API_KEY；接入信息.txt 里会列出本机的局域网地址。

五、改参数
  方法 1（最省事）：双击「启动.bat」，按 C，一步步选：
    第 1 步  模型：Swift-Bonsai-2（推荐）/ Bonsai-2 原版（没下载的，配置完按回车后自动下载）
    第 2 步  KVMem 开 / 关
    第 3 步  KV 量化：int8 / rk8v4
    第 4 步  看图：开 / 关（视觉权重放内存，开和关能开的大小一样）
    第 5 步  总上下文
    第 6 步  单次回答上限（KVMem 可输入 auto；检索窗口输入 0 表示自动）
    第 7 步  思考长度上限
    每一步都标了推荐值和上限，直接回车 = 保持现在的值；也可以直接输入数字（例如 96k），超过上限会让你重输。
    选完回到配置总览，回车启动；选好的值会自动存进「设置.ini」，下次回车直接用。
  方法 2：用记事本打开「设置.ini」修改，保存后重新运行「启动.bat」。每一项都有说明。
  方法 3：命令行临时改（不改设置文件）。在这个文件夹的地址栏输入 cmd 回车，然后：
    启动.bat kvmem                      直接用 KVMem 模式，不显示菜单
    启动.bat normal PORT=8085           普通模式，换个端口
    启动.bat kvmem KVMEM_ANSWER=auto    自动分配回答空间，优先保留 36K 检索窗口
    启动.bat kvmem KVMEM_ANSWER=8192    手动设置回答上限为 8K
    启动.bat kvrk KVRK_ANSWER=65536     手动设置为 64K；启动前会检查可用显存
    启动.bat normal --greedy            在最后追加引擎参数
    启动.bat kvmem DRYRUN=1             只显示最后会用的参数，不启动（检查设置用）
  「设置.ini」里的任何一项都能写成 名字=值 放在命令行里。
  测试别的端口：测试.bat PORT=8085

六、常见问题
  - 提示“已经有一个 ninfer-serve 在运行”：先关掉旧的引擎窗口；找不到窗口就在任务管理器里结束 ninfer-serve.exe。
  - 提示“端口已被占用”：改 设置.ini 里的 PORT。
  - 启动报显存不足（out of memory）：关掉占显存的程序（游戏、浏览器硬件加速等），或者把上下文调小。
  - 上限是按"显示器接在这张 3060 上、桌面占约 1.3 GB"算的，开到上限时整卡还剩约 200 MiB。
    同时开着游戏、视频、浏览器硬件加速等吃显存的程序，可能变很慢或起不来，这时往下调一档（4K）。
    显示器接在核显上的话，显存更宽裕。
  - 显卡不是算力 8.6：这个包是给 RTX 30 系编译的，其他显卡用不了。
  - 窗口一闪就没了：在文件夹地址栏输入 cmd 回车，再输入 启动.bat，就能看到错误信息。
  - 模型下载慢或断了：直接关掉窗口，重新运行 启动.bat，会接着下（不会从头来）。
  - 提示"文件校验不对"：把 model 文件夹里的 .bad 文件删掉，重新运行 启动.bat 下载。

七、文件夹里有什么
  启动.bat / 测试.bat     双击用（另附「设置显卡功耗.bat」可一键将 3060 功耗设为 135W 降温）
  设置.ini                参数
  launcher\               启动器脚本
  engine\                 引擎（第十轮版，2026-10-03；四种模式共用）
  model\                  模型（包里是空的，第一次启动自动下载到这里）
  SHA256SUMS.txt          核心文件校验清单
  verify-kit-manifest.ps1 解压完整性与防乱码自检脚本
  verify-arch-engine.ps1  引擎实机功能（NVML 显存预算 + KVMem 挑块 + 藏针）自检脚本
  current-mode.txt        上次用的模式（自动生成，没有也没关系）
  接入信息.txt            客户端怎么填（每次启动自动生成）

八、模型下载
  包里不带模型。第一次启动时，选好配置按回车后，会显示要下载的模型、大小和保存位置，再按一次回车开始下载。
    Swift-Bonsai-2（推荐）：https://www.modelscope.cn/models/fyb423/Swift-Bonsai-2-27B-NInfer
                             文件 bonsai2_27b_swift_pq2.ninfer
    Bonsai-2 原版         ：https://www.modelscope.cn/models/Lxt1992/ninfer-ternary-bonsai2
                             文件 models/ternary-bonsai-2-27b.ninfer（放进 model 文件夹时不要带 models 这一层）
    两个文件都是 8,306,927,628 字节（约 7.7 GiB）。
  - 用的是 Windows 自带的 curl 下载，窗口里会显示进度和速度；中途关掉窗口，下次启动会接着下。
  - 下载时先存成 xxx.ninfer.part，下完自动校验 SHA256，对了才改成正式文件名。
  - 也可以自己用浏览器或下载工具从上面的网页下载，放进 model 文件夹（文件名不要改），启动时就不会再下载。
  - 两个模型可以都下，在向导第 1 步随时切换。
  - 下载前会先检查显卡和硬盘空间，不合适的电脑不会白下 8 GB。

九、2026-10-03 第十轮更新
  - 使用 CUDA 13.3 构建；计算时读取显卡实际 SM 数量。发行包仍只支持算力 8.6。
  - KVMEM_WINDOW / KVRK_WINDOW 默认 0（检索上限 36K）；KVMEM_ANSWER / KVRK_ANSWER 默认 auto。
    按启动前的空闲显存预算分配窗口：检索窗口上限 36K，若还有显存余量则全部给输出窗口（int8 最高 40K，rk8v4 最高 64K）；
    输出窗口不得低于 8K，当剩余显存不足以给输出留够 8K 时，自动缩减检索窗口（最低到 16K）以保证输出至少为 8K。
    用户仍可在向导或 设置.ini 中手动调整输出窗口（至少 8K）和检索窗口（16K–36K）。
  - 如果引擎报告可用容量低于启动预算，自动重新分配窗口，最多调整三次；必要时联动降低输出上限。
    普通报错、主机内存锁页失败不做缩窗重试，需要按实际错误处理。
  - 四种模式统一分段读入 512 token。检索评分最多取 512 行，尽量沿换行边界取尾部；
    固定开头、本轮新内容等已保留部分从重复评分中排除，历史 KV 使用批量拷贝。
  - 核心验证：100K 长对话七轮回归通过，快速困惑度报告与旧版一致，批量拷贝逐字节比对通过。
    固定提示词新旧交替测速约 54 token/s，输出一致；本轮主要改善适配和容量分配，未测出明显提速。
  - 升级时备份旧目录。如果要保留旧 设置.ini 的个人选项，可逐项合并；
    想启用新的自动分配，请将两个 WINDOW 项改成 0、两个 ANSWER 项改成 auto。
  - 2026-10-03 晚间同步更新（与 Swift 1.5 六项改进对齐）：
    1) 引擎启动时结合 NVML 读取真实物理空闲显存（取 cudaMemGetInfo 与 nvml 的较小值），避免 Windows WDDM 虚报显存导致桌面卡顿；
    2) 开启 NINFER_TERNARY_KVMEM=1 时默认启用内容相关性挑块评分（kvmem_score: SELECT）；
    3) HTTP 服务端启用长连接保活（Keep-Alive 120s、读写超时 300s、Windows TCP Keep-Alive 10s/3s），减少连接中断；客户端等待超时仍需单独设置；
    4) 默认开启思考后自动降温（--post-thinking-temperature 0.2，思考保持 1.0，</think> 后自动切到 0.2 稳定工具调用和代码输出）与对支持的部分内部状态错误尝试恢复（有次数上限）（--recover-invariant-failures）；
    5) 新增「设置显卡功耗.bat」（或启动菜单按 P）一键设置 135W 功耗墙并注册开机自动生效，长跑温度稳在 80°C 左右不降频；
    6) 新增 SHA256SUMS.txt、verify-kit-manifest.ps1 与 verify-arch-engine.ps1 自检脚本，启动前自动检查 engine 文件夹 DLL 完整性。

2026-10-04：启动与验收共性修复
  - 使用 listening 日志判断引擎已开始服务，不再按运行不足 120 秒猜测启动失败。
    启动期的容量错误才触发缩窗；运行中退出使用有上限的重启。
  - 缩窗后同步本次实际输出上限到客户端接入信息（文字及 YAML）；
    本机启动器在允许同步时也更新 dsh。保存的个人配置不写入临时缩窗结果。
    输出预算减少时，思考预算一并限制到有效输出范围。
  - 启动失败返回非零状态。
  - 引擎验收返回码：0 为本次检查通过，1 为失败，2 为无法确认。
    FAIL 和 INCONCLUSIVE 不再被当作成功；负对照必须回答 NONE。
  - 验收新增缩短历史、实际输出封顶、真实工具结果回传、Messages / Responses 和看图。
    默认使用小窗口与 512 token 输出上限，不代表已经测满 256K 或生成满 32K。
    多工具 required/any 按 Auto 处理，不保证调用；strict 不提供严格 Schema 约束。
  - 如模型不在默认 model 目录，验收时传 -ModelPath 指定已转换文件：
      powershell -NoProfile -ExecutionPolicy Bypass -File verify-kit-manifest.ps1
      powershell -NoProfile -ExecutionPolicy Bypass -File verify-arch-engine.ps1 -ModelPath <模型文件>
    默认请求等待为 1800 秒；客户端仍需自行设置足够的等待时间。
  - 此轮修改启动与验收脚本，不改变模型量化、引擎二进制或容量配比。
